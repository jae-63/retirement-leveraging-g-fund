# Retirement Leveraging G Fund

Tools for a two-bucket, decumulation-phase retirement income strategy built around the
federal TSP G Fund as a Sequence-of-Returns-Risk (SRR) shield.

The core idea: the G Fund is principal-protected and instantly liquid, so it serves as
the household's operating cash account — monthly bills are paid straight out of it,
meaning equities never have to be sold to cover routine expenses. A Quarterly Refill
Engine decides, each quarter, whether it's safe to harvest equity gains and roll them
back into the G Fund to top the shield up, gated by an annual hurdle model that compares
household wealth against a real-growth (COLA + baseline) target.

## What's in this repo

Two Excel workbooks, each generated by its own Python script (`openpyxl`) and committed
alongside the script that produced it:

| Script | Workbook | Purpose |
|---|---|---|
| `generate_household_portfolio_engine.py` | `household_portfolio_engine.xlsx` | The live tracker. Generic placeholder data on generation; meant to be hand-maintained afterward. |
| `generate_scenario_demo.py` | `household_portfolio_scenario_demo.xlsx` | A standalone demo with a Bear/Bull/Choppy market-scenario selector, for sharing with a financial advisor or posting publicly. Fully self-contained illustrative data — never real numbers. |

### The live tracker (`household_portfolio_engine.xlsx`)

Five tabs, in order:

1. **Documentation** — motivation, a quarterly checklist, the color legend, and a glossary.
2. **Variables_And_Log** — annual COLA/hurdle inputs, a monthly TSP → checking payment
   log, a Roth conversion tax-cost log, and an annual Actual Balance log.
3. **Account_Tracker** — a manually-updated snapshot of every account's balance; the
   single source of truth for household net worth.
4. **The_Refill_Engine** — the decision-making tab. Every configured input (retirement
   start year, ramp length, G Fund target percentages, etc.) is laid out as
   Default / Override / Effective columns. The Quarterly Refill Engine table is the
   primary output; below it, the Annual SRR Hurdle Model decides GOOD vs. POOR for the
   year (using wealth adjusted for any logged Roth conversion cost, so a planned tax
   bill is never mistaken for a market downturn), and the Emergency Liquidity Protocol
   gives a next-dollar draw-down order if the shield is ever exhausted.
5. **Graph** — a read-only chart (Original vs. Current vs. Actual household wealth by
   year), kept on its own tab so it never crowds the data-entry tabs.

**Workflow**: the generator script runs *once* to scaffold the workbook with generic
placeholder data. The generated `.xlsx` is then imported into Google Sheets and becomes
the long-lived, hand-maintained document — real account balances and payment amounts get
typed in there, not regenerated from the script.

### The scenario demo (`household_portfolio_scenario_demo.xlsx`)

Same four-tab shape as the live tracker (Documentation / Variables_And_Log /
Account_Tracker / The_Refill_Engine), but every input is pre-filled with generic,
illustrative numbers, and a scenario selector on The_Refill_Engine lets you flip between
three hardcoded annual return paths — Bear (front-loaded crash), Bull (steady growth),
Choppy (oscillates near the hurdle rate) — to watch the GOOD/POOR trigger actually fire
in both directions. The live tracker can't show this on its own, since it only ever
compares a live snapshot against a target; it never simulates a market move over time.

## Requirements

- Python 3 with `openpyxl` (`pip install openpyxl`)
- macOS with a licensed copy of Microsoft Excel, for verification (see below)

## Usage

```
make build   # regenerate both .xlsx files from their generator scripts
make test    # open each workbook in Excel, recalculate, and sanity-check the formulas
make all     # build then test (the default)
make clean   # remove Python build artifacts (never touches the .xlsx files)
```

`make build` only actually re-runs a generator if its `.py` file is newer than the
`.xlsx` it produces. `make test` requires Microsoft Excel — `openpyxl` never evaluates
formulas, so opening the file for real and forcing a recalculation is the only reliable
way to catch a broken one before committing. It's a sanity net, not a full guarantee:
see the comments in `scripts/verify_workbook.sh` for a known limitation in how Excel's
AppleScript bridge surfaces formula errors.

## Conventions

- **Never commit real dollar amounts.** Account balances and payment figures in both
  generator scripts must stay generic, round placeholders. Real numbers belong only in
  the hand-maintained Google Sheets copy, never back in this repo.
- **Cell color legend** (consistent across every tab in both workbooks): pale yellow =
  editable input, white = formula (don't touch), ice blue = computed summary/headline.
- **Reusability**: both workbooks use household-neutral language ("Spouse," not a name)
  so they stay shareable as a template.
